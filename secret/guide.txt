KENORACRIC — LOCAL DEVELOPMENT GUIDE
===================================

This guide is for Windows PowerShell. Run commands from the project root, the folder containing package.json. The five main folders are android (native React Native app), web (website), server (API and shared packages), windows (reserved for a future Windows app), and secret (private environment files).

REQUIREMENTS
------------
- Node.js 22 or later, with npm.
- MongoDB Community Server running locally for API data.
- Android Studio with Android SDK and an Android emulator, or a USB-connected Android phone.
- JDK 17 for building the Android app.

Use npm.cmd commands from the project root. Dependencies are installed for the npm workspace in one step.

FIRST-TIME SETUP
----------------
Install dependencies:

    npm.cmd install

The real environment files normally already exist in secret/env. If setting up a fresh checkout, create them from the examples only when they do not exist:

    if (-not (Test-Path secret/env/server.env)) { Copy-Item secret/env/server.env.example secret/env/server.env }
    if (-not (Test-Path secret/env/web.env)) { Copy-Item secret/env/web.env.example secret/env/web.env }
    if (-not (Test-Path secret/env/android.env)) { Copy-Item secret/env/android.env.example secret/env/android.env }

Open the API settings and set JWT_ACCESS_SECRET to a private random value with at least 24 characters:

    notepad secret/env/server.env
    node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"

Copy the generated value into JWT_ACCESS_SECRET. Keep the real files in secret/env private; never commit them or send them to anyone. The example files contain placeholders.

Project-root .env files for the API and website are hard links to the corresponding files in secret/env. They are already present in this checkout. If recreating them on a fresh setup, create them after the real files above:

    New-Item -ItemType HardLink -Path server/.env -Target (Resolve-Path secret/env/server.env)
    New-Item -ItemType HardLink -Path web/.env -Target (Resolve-Path secret/env/web.env)

If a target .env already exists, do not run its New-Item command again. Edit the matching file in secret/env; the project-root hard link reflects the same contents. The Android build reads `secret/env/android.env` directly.

The default MongoDB URI is mongodb://127.0.0.1:27017/kenoracric. Start the MongoDB Windows service if installed as a service:

    Start-Service MongoDB

If Windows says that service does not exist, start MongoDB using the method chosen during installation.

START THE WEBSITE AND API
-------------------------
From the project root, run:

    npm.cmd run dev

This builds the shared packages and starts the API and web development servers. Keep the terminal open. The web app is at http://localhost:5173 and the API health check is at http://localhost:5000/health. The health response should show status "ok" and database "connected".

To stop the servers, press Ctrl+C. If the API reports that JWT_ACCESS_SECRET is missing or too short, edit secret/env/server.env and restart. If the database is disconnected, start MongoDB first.

RUN ON AN ANDROID PHONE
-----------------------
The Android app is a native React Native app. The phone cannot use localhost to reach the API on your computer. Find the computer's Wi-Fi IPv4 address:

    ipconfig

Under the Wi-Fi adapter, note its IPv4 Address, for example 192.168.1.20. Edit the Android API URL:

    notepad secret/env/android.env

Set it to your computer's address, preserving the API path. Example:

    MOBILE_API_URL=http://192.168.1.20:5000/api/v1

Replace the example address with the Wi-Fi IPv4 address from ipconfig. Keep the phone and computer on the same non-guest Wi-Fi network. Allow Node.js through Windows Firewall on Private networks if prompted. Each app start or APK build reads this setting.

In a PowerShell window, from the project root, run:

    npm.cmd run android

This builds the shared packages, starts Metro, and launches the app on the connected emulator or phone. Keep the terminal open while developing. For a physical phone, enable Developer options and USB debugging, then connect it by USB.

MAKE AN ANDROID APK YOU CAN INSTALL
-----------------------------------
Install Android Studio and its Android SDK, and install JDK 17. In Android Studio's SDK Manager, install the Android SDK Platform and Build Tools required by the project. Set `ANDROID_HOME` to your SDK folder if the installer has not already configured it. Set `MOBILE_API_URL` in `secret/env/android.env` to a server URL reachable by the phone. For phones outside your Wi-Fi, use your deployed API's HTTPS URL.

Build a debug APK from the project root:

    npm.cmd run apk:debug --workspace=@kenoracric/mobile

The APK is created at `android/android/app/build/outputs/apk/debug/app-debug.apk`. Copy that file to your phone (including through WhatsApp), install it, and allow installs from that source if Android asks. The API URL is compiled into the app; the server must be running and reachable from the phone.

DEMO SCORER ACCOUNT AND MATCHES
-------------------------------
The demo seed command creates or verifies a scorer account and adds three clearly labeled DEMO completed results plus three upcoming DEMO fixtures. The records are saved in the MongoDB database configured in server/.env. It is safe to rerun: it updates those demo records by title. If the email already exists, the supplied password must match; otherwise the script stops without changing data.

Enter the scorer details in PowerShell without putting the password in a project file:

    $env:DEMO_USER_EMAIL = Read-Host "Scorer email"
    $env:DEMO_USER_NAME = Read-Host "Scorer name"
    $securePassword = Read-Host "Scorer password" -AsSecureString
    $env:DEMO_USER_PASSWORD = [System.Net.NetworkCredential]::new("", $securePassword).Password

The script blocks remote database writes by default. Since server/.env may point to a remote database, only set the explicit flag if that is the intended database:

    $env:ALLOW_REMOTE_SEED = "1"
    npm.cmd run seed:demo
    Remove-Item Env:DEMO_USER_EMAIL,Env:DEMO_USER_NAME,Env:DEMO_USER_PASSWORD,Env:ALLOW_REMOTE_SEED

The DEMO matches are fictional sample data. In the app, use the scorer workspace to sign in and score an assigned match. Change any shared or temporary password before using the account for real work.

TROUBLESHOOTING
---------------
- "react-native is not recognized": run npm.cmd install from the project root, then retry npm.cmd run android.
- Phone says "Network request failed": check the phone URL in secret/env/android.env, the API health URL on the computer, Wi-Fi, VPN, and Windows Firewall.
- No matches appear: the database may be empty. Create a match with a scorer or admin account.
- Scoring deliveries are saved to the phone's local storage before sync is attempted. Automatic replay of queued deliveries after reconnect is not implemented yet.
- npm reports deprecated packages or audit notices during install: those are warnings and do not necessarily prevent the app from running. Do not run npm audit fix --force without reviewing the dependency changes.

KENORACRIC — STEP-BY-STEP WINDOWS GUIDE
======================================

Run project commands in Windows PowerShell from the project root: the KenoraCric folder containing package.json. The five main folders are android (Android app), web (website), server (API and shared packages), windows (reserved for a future Windows app), and secret (private environment settings).

PART 1 — CHECK YOUR TOOLS
-------------------------

1. Install Node.js 22 or later. Open a NEW PowerShell window and check:

    node --version
    npm --version

2. Android Studio is installed. Open it once and complete its first-run setup wizard. Choose the Standard setup unless you have a reason to customize it. Allow the wizard to download the Android SDK and recommended components.

3. In Android Studio, open More Actions > SDK Manager (or File > Settings > Languages & Frameworks > Android SDK). On the SDK Platforms tab, install Android 15 / API 35.

4. In SDK Manager, open the SDK Tools tab and install or confirm these components:

    Android SDK Build-Tools 35.0.0
    Android SDK Platform-Tools
    Android SDK Command-line Tools (latest)
    NDK (Side by side) 26.1.10909125
    Android Emulator (only needed if you want an emulator)

Select Apply and let Android Studio finish downloading. The project uses compile SDK 35 and NDK 26.1.10909125.

5. Find the Android SDK path shown at the top of the SDK Manager. The usual Windows path is:

    C:\Users\<your Windows user>\AppData\Local\Android\Sdk

6. Confirm the SDK folder exists from PowerShell. This uses the standard location; if yours differs, use the SDK path shown in Android Studio:

    Test-Path "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe"

The result should be True.

PART 2 — SET JAVA AND ANDROID SDK VARIABLES
-------------------------------------------

The Android build needs JDK 17. In Android Studio, open File > Settings > Build, Execution, Deployment > Build Tools > Gradle. Open the Gradle JDK list and choose a JDK 17 installation. If JDK 17 is not listed, choose Download JDK, select version 17, download it, then select it as the Gradle JDK. Note the selected JDK's full folder path. Android Studio's bundled `jbr` may be a different Java version, so check `java -version` rather than assuming it is 17.

The `JAVA_HOME` value set with `$env:` lasts only for that PowerShell window. That is why a new terminal can fail with “JAVA_HOME is not set,” even if the APK built successfully before. Set it once as a Windows user variable so new terminals can find Java.

In Android Studio, open File > Settings > Build, Execution, Deployment > Build Tools > Gradle and find the selected Gradle JDK. Use that JDK 17 folder below. JAVA_HOME must point to the folder containing `bin\java.exe`, not to the `bin` folder itself. For example, if Android Studio shows a Microsoft JDK under your user folder, use that exact JDK path in place of the example.

In PowerShell, set JAVA_HOME to the actual JDK 17 folder and run:

    $jdkHome = "C:\Program Files\Android\Android Studio\jbr"
    if (-not (Test-Path "$jdkHome\bin\java.exe")) { throw "Java not found. Replace `$jdkHome with the JDK 17 folder shown in Android Studio > Gradle settings." }
    [Environment]::SetEnvironmentVariable("JAVA_HOME", $jdkHome, "User")
    [Environment]::SetEnvironmentVariable("ANDROID_HOME", "$env:LOCALAPPDATA\Android\Sdk", "User")
    $env:JAVA_HOME = $jdkHome
    $env:ANDROID_HOME = "$env:LOCALAPPDATA\Android\Sdk"
    $env:Path = "$env:JAVA_HOME\bin;$env:ANDROID_HOME\platform-tools;$env:ANDROID_HOME\emulator;$env:Path"
    java -version
    adb version

If the example JDK path is not present, replace the first line with the exact Gradle JDK location in Android Studio. `java -version` should report version 17; `adb version` should work. The Windows user variables persist for future terminals, and the `$env:` lines make them available immediately in this window. Close and reopen PowerShell once to confirm they persist.

You can now run the APK command from the project root in that same window:

    npm.cmd run apk:release --workspace=@kenoracric/mobile

PART 3 — INSTALL PROJECT PACKAGES
---------------------------------

1. In PowerShell, change to the project root. Example:

    cd "C:\Users\Rajpa\OneDrive\Desktop\KenoraTech\Andorid Apps\KenoraCric"

2. Install npm workspace dependencies:

    npm.cmd install

Wait until npm exits and returns to the PowerShell prompt. Warnings about deprecated packages are not necessarily install failures. If npm ends with an error, fix that error before continuing.

PART 4 — PREPARE PRIVATE SETTINGS AND MONGODB
---------------------------------------------

Real settings belong under secret/env. On a new checkout, copy each example only if its real file is missing:

    if (-not (Test-Path secret/env/server.env)) { Copy-Item secret/env/server.env.example secret/env/server.env }
    if (-not (Test-Path secret/env/web.env)) { Copy-Item secret/env/web.env.example secret/env/web.env }
    if (-not (Test-Path secret/env/android.env)) { Copy-Item secret/env/android.env.example secret/env/android.env }

Set a private JWT secret in secret/env/server.env. Generate one with:

    node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"

Open the file, replace the JWT_ACCESS_SECRET placeholder with the generated value, and save:

    notepad secret/env/server.env

Do not share or commit real environment files. The API and web workspaces use their `.env` hard links. The Android build reads secret/env/android.env directly.

Install MongoDB Community Server if it is not installed. The default database URL is mongodb://127.0.0.1:27017/kenoracric. If MongoDB was installed as a Windows service, start it from PowerShell:

    Start-Service MongoDB

If that service name is not found, start MongoDB using the option chosen during MongoDB installation.

PART 5 — START THE API AND WEBSITE
----------------------------------

1. In the project root, start both services:

    npm.cmd run dev

2. Leave this PowerShell window open. The website should open at http://localhost:5173. Check the API at http://localhost:5000/health; it should report status `ok` and database `connected`.

3. To stop the services, press Ctrl+C. If the API says the JWT secret is missing or too short, check secret/env/server.env. If the database is disconnected, start MongoDB.

PART 6 — SET THE API ADDRESS FOR YOUR ANDROID DEVICE
----------------------------------------------------

The phone cannot use `localhost` to reach an API running on your computer. Choose the correct address:

- Android emulator: use http://10.0.2.2:5000/api/v1
- Physical phone on the same Wi-Fi: use the computer's Wi-Fi IPv4 address, for example http://192.168.1.20:5000/api/v1
- Phone connecting from outside your home/office network: deploy the API and use its public HTTPS address.

For a physical phone, find the computer's Wi-Fi IPv4 address with:

    ipconfig

Find the IPv4 Address under the Wi-Fi adapter. Edit the Android setting:

    notepad secret/env/android.env

Set MOBILE_API_URL to the chosen address, with the `/api/v1` ending. Example for a phone on the same Wi-Fi:

    MOBILE_API_URL=http://192.168.1.20:5000/api/v1

Use your actual IP address, not the example. The address is compiled into the APK when you build it. Rebuild after changing it. Keep the phone and computer on the same non-guest Wi-Fi and allow Node.js through Windows Firewall on Private networks if Windows asks.

PART 7 — RUN THE APP ON A CONNECTED PHONE OR EMULATOR
-----------------------------------------------------

Option A: use a physical Android phone over USB.

1. On the phone, open Settings > About phone and tap Build number seven times to enable Developer options. Menu names can vary by phone manufacturer.
2. In Settings > Developer options, turn on USB debugging.
3. Connect the phone to the computer with a data-capable USB cable. Unlock the phone and accept the USB debugging prompt.
4. In PowerShell at the project root, check that Android can see it:

    adb devices

The phone should appear with status `device`. If it says `unauthorized`, unlock the phone and accept the prompt. If it does not appear, try another cable/USB port and install the phone manufacturer's USB driver if Windows needs one.

Option B: use an Android emulator.

1. In Android Studio, open Device Manager and create a virtual phone if one does not already exist.
2. Start the emulator and wait for its home screen.
3. Use the emulator API address from Part 6: http://10.0.2.2:5000/api/v1.

Start the app from the project root:

    npm.cmd run android

This builds the shared packages, starts Metro, builds the Android app, and installs it on the detected device. Keep the terminal open while developing. To stop, press Ctrl+C.

PART 8 — BUILD A STANDALONE APK FOR INSTALLING OR SENDING
---------------------------------------------------

1. Make sure Java, Android SDK, adb, npm dependencies, and MongoDB are set up in the earlier steps.
2. Set MOBILE_API_URL in secret/env/android.env to an API address reachable by the target phone. For a phone on your local Wi-Fi, use your computer's Wi-Fi IP. For someone outside your network, use your deployed API's HTTPS address. Do not use localhost or the emulator-only 10.0.2.2 address in an APK intended for a physical phone.
3. In PowerShell, change to the project root and build the release APK. This bundles the JavaScript into the APK, so Metro does not need to be running on the phone:

    npm.cmd run apk:release --workspace=@kenoracric/mobile

4. Wait for Gradle to finish and for the command to return to the PowerShell prompt. A successful build ends with `BUILD SUCCESSFUL`.
5. In File Explorer, open this exact path under the project root:

    android\android\app\build\outputs\apk\release\app-release.apk

You can also open the folder from PowerShell:

    explorer.exe android\android\app\build\outputs\apk\release

6. Copy `app-release.apk` to the phone using USB, cloud storage, or WhatsApp. On the phone, tap the APK and allow installation from that app/source if Android asks. The app requires the API server to be running and reachable at the address compiled into the APK.

This release APK is configured with a debug signing key for personal testing and sharing. It is not ready for publishing in an app store. Keep using the same API URL or rebuild the APK when that URL or the app icon changes. The separate `apk:debug` build is for development with Metro running; do not send that APK as a standalone app.

PART 9 — DEMO SCORER AND MATCHES (OPTIONAL)
-------------------------------------------

The seed command creates or verifies one scorer account and adds three fictional DEMO completed results plus three upcoming DEMO fixtures in the MongoDB configured for the API. If the email already exists, the provided password must match or the script stops without changing data.

Enter the account information in PowerShell without saving the password in a project file:

    $env:DEMO_USER_EMAIL = Read-Host "Scorer email"
    $env:DEMO_USER_NAME = Read-Host "Scorer name"
    $securePassword = Read-Host "Scorer password" -AsSecureString
    $env:DEMO_USER_PASSWORD = [System.Net.NetworkCredential]::new("", $securePassword).Password

The script blocks remote database writes unless you explicitly confirm them. Only set this flag if the configured database is the intended target:

    $env:ALLOW_REMOTE_SEED = "1"
    npm.cmd run seed:demo
    Remove-Item Env:DEMO_USER_EMAIL,Env:DEMO_USER_NAME,Env:DEMO_USER_PASSWORD,Env:ALLOW_REMOTE_SEED

The sample matches are fictional. Change any temporary/shared password before real use.

TROUBLESHOOTING
---------------

- `java is not recognized` or Gradle says JAVA_HOME is missing: Android Studio/JDK was not found at the configured path. Check the Gradle JDK location in Android Studio, point JAVA_HOME to its JDK 17 folder, add `%JAVA_HOME%\bin` to Path, open a new PowerShell window, and confirm `java -version` works.
- `SDK location not found`: install the SDK in Android Studio's SDK Manager, then set ANDROID_HOME to the SDK path shown there. Open a new PowerShell window.
- `adb is not recognized`: add `%ANDROID_HOME%\platform-tools` to Path, open a new PowerShell window, and run `adb version`.
- Build stops before Gradle: check that `npm.cmd install` completed successfully and rerun the command from the project root.
- APK folder is missing: Gradle has not completed successfully yet. Find the first `FAILURE` or `ERROR` in the terminal output and resolve it; the APK is written only after `BUILD SUCCESSFUL`.
- `Unable to load script` when opening the installed app: that is the debug APK, which expects Metro. Build and install the standalone APK using Part 8 (`apk:release`).
- Phone says `Network request failed`: check MOBILE_API_URL, verify http://localhost:5000/health works on the computer, confirm phone/computer network access, and check Windows Firewall.
- No matches appear: the database may be empty. Create a match with an authorized scorer/admin or run the optional demo seed instructions above.
- Scoring deliveries are saved to local storage before sync is attempted. Automatic replay of queued deliveries after reconnect is not implemented yet.
- npm deprecation/audit warnings do not necessarily stop the app. Avoid `npm audit fix --force` without reviewing the changes.
